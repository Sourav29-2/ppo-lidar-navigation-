========================================
NAV2 PATH FEATURE ANALYSIS
========================================

Nav2 path topic: /plan
Message type: nav_msgs/Path
Frame: map
Typical path length: 70-80 poses for open goals, 150-180 for obstacles, 290-340 for wall-blocked detours.
Path update behavior: The path updates at roughly 1Hz (or whenever the robot moves significantly/new obstacles appear). The path remains smooth and the number of poses slowly decreases as the robot progresses towards the goal. The feature extraction handles path replacements perfectly.

----------------------------------------
SELECTED FEATURES
----------------------------------------

Feature: Robot-Relative Lookahead Waypoints
Dimension: 10 values (5 pairs of x,y coordinates)
Range: [-2.5, 2.5] meters
Normalization: Divide by 3.0 (i.e. x_norm = x/3.0, y_norm = y/3.0)
Reason: By sampling at fixed distances (0.5m, 1.0m, 1.5m, 2.0m, 2.5m) along the global path, we get a stable, fixed-size mathematical representation of the upcoming path shape regardless of how many poses Nav2 generated. By transforming these into the robot's local frame (`base_footprint`), the PPO agent receives egocentric "breadcrumb" vectors. The maximum physical distance is 2.5m, so dividing by 3.0 guarantees all values stay within [-1.0, 1.0], which is perfectly scaled for neural network inputs.

----------------------------------------
CRITICAL QUESTION
----------------------------------------

Can the proposed Nav2 path representation provide PPO with useful global-route information that it currently lacks?

Answer:
    YES

Explanation:
Our diagnostic data proves that this representation easily distinguishes between a clear route and a wall-blocked route. In the Open Goal scenario, the 10 values are heavily weighted towards positive X (forward). In the Wall-Blocked scenario, despite the goal coordinates being physically located in front of the robot, the 10 path features are heavily weighted towards negative X (backwards/detour). The PPO agent currently only has Goal + LiDAR. It has no idea the wall is infinite until it gets stuck. By adding these 10 normalized waypoint values, PPO will immediately "see" that the correct path is to turn around and follow the global route.
